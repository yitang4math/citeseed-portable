# 标准工作流：单篇论文「核心启发文献」识别

> 用途：给定一篇论文全文，产出 **1–3 篇真正引发该研究的参考文献**，每篇附逐字原文证据、影响类型与把握程度。
> 本文件只描述可执行的操作。所有步骤均可照抄执行，方括号内为待替换的占位符。

---

## 一、输入说明

| 输入项 | 必需性 | 形式要求 | 说明 |
|---|---|---|---|
| 论文全文 PDF | **必需** | **文本型**（可选中复制文字）；扫描件需先 OCR | 双栏（IEEE/Springer）、单栏（arXiv/ICLR/ACL LaTeX）均支持 |
| 参考文献列表 | 可选 | `.bib`（首选）/ `.txt`（一行一条）/ `.json` | 不提供时脚本自动从 PDF 尾部解析；解析异常时此项作为兜底与纠错手段 |
| 联网 | 可选 | 仅 `--metadata`、`--llm` 两步需要 | 核心流程离线可跑完 |
| LLM API Key | 可选 | 环境变量 `LLM_API_KEY` | 仅 `--llm` 自动裁决需要；不配置则走人工裁决 |

**不适用的输入**：纯图片 PDF（未 OCR）、仅有摘要页、参考文献与正文分离的预印本残卷。

---

## 二、前置准备清单

一次性准备，之后每次执行只需替换占位符。

- [ ] **P1 运行时**：Python 3.9+，已安装 `pymupdf`（其余 `networkx`/`pandas` 仅关系图谱步骤需要）。
      本机受管环境：`<PY>` = `<PY>`
- [ ] **P2 脚本就位**：`citeparse.py`、`seedfinder.py`（关系图谱另需 `citegraph.py`）位于工作目录 `citetool/`。
- [ ] **P3 工作目录**：创建独立输出目录，一篇论文一个目录，不要复用。
- [ ] **P4 PDF 落盘**：把目标 PDF 放到可访问路径，路径建议不含空格与中文以外的特殊字符。
- [ ] **P5 参考文献基线数**（人工）：翻到论文末尾，目测参考文献总条数，记为 `<N_expected>`。
      **这一步是后续所有校验的分母，不能省。**
- [ ] **P6**（可选）配置 `LLM_API_KEY`；如需补全元数据，准备 OpenAlex / Semantic Scholar key。

---

## 三、占位符约定

| 占位符 | 含义 | 取值来源 |
|---|---|---|
| `<PY>` | Python 解释器路径 | 见 P1 |
| `<PDF>` | 论文 PDF 路径 | 输入 |
| `<REFS>` | 外部参考文献文件（可选） | 输入 |
| `<OUT>` | 输出目录名 | 自定义，如 `out_<论文代号>` |
| `<N_expected>` | 人工目测的参考文献总条数 | P5 |
| `<STYLE>` | 引用标记制式 | `numeric`（`[3]`）或 `authoryear`（`(Author, 2024)`） |

## 四、主流程

### S0 环境就绪检查

- **前置条件**：P1–P4 完成。
- **输入**：无。
- **动作**：

```bash
<PY> -c "import pymupdf; print(pymupdf.__doc__)"
ls citeparse.py seedfinder.py
```

- **预期输出**：pymupdf 版本信息；两个脚本文件存在。
- **校验点**：命令无 `ModuleNotFoundError`、无 `No such file`。
- **异常处理**：缺包 → `pip install pymupdf` 后重试；脚本缺失 → 回到 P2。

---

### S1 PDF 体检

- **前置条件**：S0 通过。
- **输入**：`<PDF>`。
- **动作**：

```bash
<PY> -c "
import pymupdf
d = pymupdf.open(r'<PDF>')
print('pages', len(d))
print('toc', len(d.get_toc()))
t = d[0].get_text('text')
print('p0 chars', len(t))
print(t[:400])
"
```

- **预期输出**：页数 > 0；首页字符数 > 300（**这是文本层的判据**）；首页文字可辨认。
- **校验点**：
  1. 首页字符数 > 300 → 文本型，继续。
  2. 目录条目数 > 0 仅作参考，本项目不依赖 PDF 书签。
- **异常处理**：
  - 首页字符数 < 100 → 扫描件或纯图片，**终止**，先做 OCR 再回到 S1。
  - 中文/公式显示为乱码 → 记录该现象，后续人工复核时以 PDF 原文为准，不采信抽取文本。

---

### S2 引用制式判定（分支准备）

- **前置条件**：S1 通过。
- **输入**：`<PDF>`。
- **动作**：在正文前几页检索两种标记形态：

```bash
<PY> -c "
import pymupdf, re
d = pymupdf.open(r'<PDF>')
t = ''.join(d[i].get_text('text') for i in range(0, min(6, len(d))))
print('numeric  [n] :', len(re.findall(r'\[\d{1,3}\]', t)))
print('authoryear   :', len(re.findall(r'[A-Za-z]+ et al\.\s*\(\d{4}\)|\(\s*[A-Za-z]+ (?:and|&)?[^)]{0,60}\d{4}\s*\)', t)))
"
```

- **预期输出**：两种计数中一种显著占优。
- **校验点**：占优形态即为 `<STYLE>`，记入 S3。
- **异常处理**：两者都接近 0 → 该稿可能用上标数字或脚注式引用，**在 S3 显式传 `--style numeric` 并跳到 S4 重点核查上下文数**；仍为 0 则改用 `--refs` + 人工标注路径（见 S4 异常表）。

---

### S3 引用抽取

- **前置条件**：S2 完成，已确定 `<STYLE>`。
- **输入**：`<PDF>`、可选 `<REFS>`、`<OUT>`。
- **动作**（默认路径）：

```bash
<PY> citeparse.py r'<PDF>' --out <OUT>
```

**分支开关**（按场景叠加，不是每次都加）：

| 条件 | 追加参数 | 说明 |
|---|---|---|
| 需要提供外部参考文献，或 S4 判定自动解析失败 | `--refs <REFS>` | `.bib` / `.txt` / `.json` 均可 |
| S2 判定结果与实际不符，或抽取上下文数为 0 | `--style <STYLE>` | 覆盖自动检测 |
| **需要覆盖附录中的竞争者对比**（默认在参考文献处停止扫描） | `--appendix` | 若只关心正文证据，保持关闭以维持结果稳定 |

- **预期输出**：

```
[refs] 载入 <N_refs> 条参考文献
[out] <OUT>/meta.json
[out] <OUT>/contexts.json
...
```

- **校验点**：见 S4（本步不单独验收，交由 S4 统一闸口）。
- **异常处理**：命令报错 → 检查路径引号与转义；其余异常统一在 S4 处理。

---

### S4 抽取质量闸口（**不可跳过**）

- **前置条件**：S3 执行完毕。
- **输入**：`<OUT>/meta.json`、`refs_nodes.json`、`contexts.json`。
- **动作**：一次性打印全部校验指标：

```bash
<PY> -c "
import json, collections, re, csv
meta = json.load(open(r'<OUT>/meta.json', encoding='utf-8'))
refs  = json.load(open(r'<OUT>/refs_nodes.json', encoding='utf-8'))
ctxs  = json.load(open(r'<OUT>/contexts.json', encoding='utf-8'))
print('style      :', meta['style'])
print('n_refs     :', meta['n_refs'])
print('n_ctx      :', meta['n_ctx'])
print('n_sent     :', meta['n_sent'])
print('被引用文献数:', len({c['ref_id'] for c in ctxs}))
print()
print('章节分布:', dict(collections.Counter(c['section'] for c in ctxs).most_common(10)))
print()
bad_year = sum(1 for r in refs if not r.get('year'))
bad_title= sum(1 for r in refs if not r.get('title') or len(r.get('title','')) < 15)
same_raw = sum(1 for r in refs if r.get('title') and r['title'] == r.get('raw','')[:len(r['title'])])
print('缺年份条目 :', bad_year, '/', len(refs))
print('题名过短   :', bad_title, '/', len(refs))
print('题名=整条书目:', same_raw, '/', len(refs))
"
```

- **验收判据（全部满足才进入 S5）**：

| # | 判据 | 阈值 |
|---|---|---|
| C1 | 参考文献条目数 | `<N_refs>` 与 `<N_expected>` 相差 ≤ 2 |
| C2 | 被引用文献覆盖 | ≥ 50% 的文献至少有 1 条上下文 |
| C3 | 上下文总量 | `n_ctx` ≥ `<N_refs>` × 1.2 |
| C4 | 章节分布 | ≥ 3 个不同章节；单一章节占比 < 80%；**引言与相关工作必须各有上下文** |
| C5 | 制式 | `meta['style']` 与 S2 判定一致 |
| C6 | 元数据 | 缺年份条目 < 10%；「题名 = 整条书目原文」的条目 < 10% |
| C7 | 匹配抽查 | 随机抽 3 条上下文，其 `ref_id` 对应的题名与句中作者/年份对得上 |

- **异常处理**（按现象定位，逐条处理，每条处理后**重跑 S3 再回到 S4**）：

| 现象 | 可能原因 | 处理动作 |
|---|---|---|
| C1 失败，`n_refs` = 0 | 书目无编号（作者列表式），或参考文献区标题未被定位 | 传 `--refs <REFS>` 提供外部书目 |
| C1 失败，`n_refs` 远小于预期（个位数） | 参考区结束判据被表格列名/正文标题误触发 | 传 `--refs <REFS>` 绕过解析 |
| C1 失败，`n_refs` 远大于预期 | 附录正文混入书目 | 传 `--refs <REFS>`；若必须自动解析，确认附录标题含 `Appendix`/`Supplementary`/`A ` 等语义词 |
| C2/C3 失败，上下文极少 | 引用制式误判 | 显式传 `--style numeric` 或 `--style authoryear` |
| C2/C3 失败，作者-年匹配全部落空 | 书目作者串格式特殊（如 "Surname, Given"、多人并列） | 传 `--refs <REFS>` 提供规范化书目 |
| C4 失败，上下文集中于单一章节或大量落在 `(正文开头)` | **章节标题未被识别**（罗马数字编号、编号与标题分行、全大写标题） | 不修脚本：直接在 S6 改用 `contexts.json` 的 `page` 字段定位原文，人工按页码回查；若希望自动修，补充标题正则后重跑 |
| C7 失败 | 引用匹配错位 | 传 `--refs <REFS>`；仍错则本稿不适用自动路径，转人工 |
| C6 失败 | 书目条目切分异常（题名与作者/出处粘连） | 传 `--refs <REFS>`；或在 S6 直接读 `refs_nodes.json` 的 `raw` 字段人工抄录题录 |

---

### S5 候选压缩与证据包生成

- **前置条件**：S4 全部判据通过。
- **输入**：`<OUT>`。
- **动作**：

```bash
<PY> seedfinder.py <OUT> --top 8
```

可选叠加：`--metadata`（联网补全作者/题名/年份/出处；需要网络）。

- **预期输出**：
  - `<OUT>/seeds_ranked.csv` — 全表排序（每行含：ref_id、score、作者、题名、年份、出处、出现次数、出现章节、主角色、次角色、把握程度、疑似次要、排除理由、缺失信息、最强证据原文、最强证据章节、最强证据页码）
  - `<OUT>/seeds_ranked.md`
  - `<OUT>/seeds_evidence_pack.md` — 前 N 名的 ±2 句上下文证据包
  - `<OUT>/seeds_prompt.md` — 供 LLM 裁决的提示词
- **校验点**：`seeds_ranked.csv` 行数 = 被引用文献数；`最强证据原文` 列非空。
- **异常处理**：文件缺失 → 确认 S3 的 `contexts.json` 非空；`--top` 超出候选数时按实际数量截断，不报错。

---

### S6 候选复核（机器排序的定序合法性判定）

- **前置条件**：S5 完成。
- **输入**：`<OUT>/seeds_ranked.csv`。
- **动作**：

```bash
<PY> -c "
import csv
rows = list(csv.DictReader(open(r'<OUT>/seeds_ranked.csv', encoding='utf-8-sig')))
for i, r in enumerate(rows[:12], 1):
    flag = '次要' if r['疑似次要'] == '是' else '    '
    print(f\"{i:>2}. [{r['ref_id']:>2}] {float(r['score']):>6} {r['把握程度']:<3} {r['主角色']:<16}{flag} 次{r['出现次数']:>2} {r['题名'][:50]}\")
print()
s1, s4 = float(rows[0]['score']), float(rows[min(3, len(rows)-1)]['score'])
print('Top1/第4名 =', round(s1 / s4, 2))
"
```

- **验收判据**：
  - **R2 定序阈值**：`Top1 / 第4名 ≥ 2.0` → 排序可直接用于定序；`< 2.0` → **排序只用于圈定候选集，不得用于定序**，必须进入 S7 按证据裁决。
  - 标记「疑似次要」的行不进入前 3 名候选。
- **异常处理**：候选数 < 3 → 直接进 S7，并在交付物中注明候选不足的原因。

---

### S7 人工裁决（定序与定性）

- **前置条件**：S6 完成。
- **输入**：`<OUT>/seeds_evidence_pack.md`、`seeds_ranked.csv`，以及 PDF 原文。
- **动作**：

1. **读原文建基准**（不可省略）：打开 PDF，精读 **引言、研究动机、相关工作**三节，用检索定位关键句式：

```bash
<PY> -c "
import pymupdf, re
d = pymupdf.open(r'<PDF>')
t = ''.join(d[i].get_text('text') for i in range(0, min(4, len(d))))
for kw in ['inspire', 'motivat', 'to date', 'only been', 'however', 'limitation', 'we build', 'we extend', 'different from']:
    for m in re.finditer(kw, t, re.I):
        s = max(0, m.start() - 180)
        print('>>>', t[s:m.start()+200].replace(chr(10), ' '))
        print()
"
```

2. **逐候选核查**：对 S6 圈定的候选（通常 ≤ 8 篇），在 PDF 中检索其被引位置，**逐字抄录**含启发语言的句子，记录章节与页码。
3. **归类影响类型**：`提出问题` / `提供方法` / `作为对比基线` / `揭示研究空白` / `提供理论基础`。
4. **定把握程度**（见 R5）。
5. **排除**：把「本文要超越/对比的对象」与「思想来源」分开，前者不进结果（见 R9）。
6. **证据不足时不补位**：凑不满 3 篇就交 1 或 2 篇，并写明缺失的关键信息（见 R8）。

- **预期输出**：交付文档（模板见第六节）。
- **校验点**：每条结论都能在 PDF 中逐字复现，并带章节 + 页码。
- **异常处理**：某候选的关键证据句在抽取文本中被截断 → 用 `contexts.json` 的 `page` 定位到原页，人工读取完整段落补录。

---

### S8（可选）LLM 裁决

- **前置条件**：S5 完成，且已配置 `LLM_API_KEY`；或手动复制提示词。
- **输入**：`<OUT>/seeds_prompt.md`。
- **动作**（二选一）：

```bash
<PY> seedfinder.py <OUT> --llm
```

或把 `seeds_prompt.md` 整段粘贴给任意长上下文模型。

- **预期输出**：1–3 篇结论，每篇附逐字原文引用。
- **校验点**：每条结论必须含逐字原文 + 章节 + 页码；证据不足的条目必须输出 `insufficient` 而非硬编。
- **异常处理**：输出无原文锚点 → 判为不可采信，回到 S7 人工裁决。

---

### S9（可选）参考文献关系图谱

仅在需要「参考文献之间的关系」这一附加产物时执行。

- **前置条件**：S4 通过。
- **输入**：`<OUT>`。
- **动作**：

```bash
<PY> citegraph.py <OUT>            # 仅用本文内部共现
<PY> citegraph.py <OUT> --enrich   # 叠加外部引用边（需 OpenAlex key）
```

- **预期输出**：边表 CSV、聚类、时间线、Mermaid 思维导图、SVG 网络图、GraphML。
- **校验点**：边表非空；聚类数 ≥ 2。
- **异常处理**：`--enrich` 报鉴权错误 → 退回不带参数的版本，此时只有「同句共现」边，语义上属局部共引而非严格共被引，需在交付物中注明。

---

### S10 产物归档

- **前置条件**：S7（或 S8）完成。
- **动作**：在 `<OUT>/` 下保留交付文档，并确认产物齐套：

```
<OUT>/
├── meta.json                 抽取元信息（style / n_refs / n_ctx）
├── refs_nodes.json           参考文献题录
├── contexts.json             引用上下文（含 page / section / 共引）
├── sentences.json            全句序列（供 ±2 句窗口回溯）
├── citation_support.csv/.md  引用—观点支撑对照表
├── seeds_ranked.csv/.md      全表排序
├── seeds_evidence_pack.md    候选证据包
├── seeds_prompt.md           LLM 裁决提示词
└── <交付文档>.md              核心启发文献结论
```

- **校验点**：交付文档中的每一条证据都能在 `contexts.json` 或 PDF 中定位。

## 五、分支决策表

按序回答，据此组装 S3 命令：

| 决策点 | 条件 | 取值 |
|---|---|---|
| D1 是否提供外部书目 | 有 `.bib`/`.txt` | `--refs <REFS>`；否则省略 |
| D2 制式是否明确 | S2 判定与实际不符 | `--style <STYLE>`；否则 `auto` |
| D3 是否关心附录中的对比 | 需要覆盖附录 | `--appendix`；否则省略 |
| D4 是否联网 | 需要补全元数据 | `--metadata` |
| D5 是否用 LLM 裁决 | 已配置 Key | `--llm`；否则 S7 人工 |

**最小命令**：`<PY> citeparse.py <PDF> --out <OUT>` → `<PY> seedfinder.py <OUT>`
**最大命令**：`<PY> citeparse.py <PDF> --refs <REFS> --style <STYLE> --appendix --out <OUT>` → `<PY> seedfinder.py <OUT> --top 8 --metadata --llm`

## 六、交付文档模板

```markdown
# <论文简称> 核心启发文献

## 元信息
- 论文：<题名>，<会议/期刊> <年份>
- 抽取统计：参考文献 <N_refs> 条，引用上下文 <N_ctx> 条，制式 <STYLE>
- 定序依据：<Top1/第4名 = X.XX，达到 / 未达到 2.0 阈值，排序 用于定序 / 仅用于圈定候选>

## 1. <作者>. <题名>. <出处>, <年份>  —— 把握：<高/中/低>
- **影响类型**：<提出问题 / 提供方法 / 作为对比基线 / 揭示研究空白 / 提供理论基础>
- **原文证据**：
  - "<逐字原文>"（<章节>, p.<页码>）
  - "<逐字原文>"（<章节>, p.<页码>）
- **具体影响**：<2–4 句>

## 2. ...
## 3. ...

## 证据不足项
- <若不满 3 篇>：明确指出缺失的关键信息是什么、需要补什么材料才能判定。

## 明确排除
- <文献>：排除理由（<高频但属基线/骨干/数据集 / 仅批量罗列 / 仅出现在附录且本文未承认继承其机制>）
```

## 七、通用规则（跨稿件适用，执行时遵守）

| # | 规则 |
|---|---|
| R1 | **排序是压缩器，不是判定器**。规则分只负责把 N 篇压到 ≤ 8 篇候选，最终 1–3 篇由证据裁决。 |
| R2 | **定序阈值**：Top1 分数 / 第 4 名分数 ≥ 2.0 时排序才可用于定序；否则必须按 S7 裁决。 |
| R3 | **出现次数与启发强度不相关**。高频引用往往是基线方法、骨干网络或数据集，属「论证对象」而非「思想来源」。 |
| R4 | **无逐字证据不写结论**。每条结论必须附原文句子 + 章节 + 页码，可回查。 |
| R5 | **把握程度分级**：高 = 在引言/动机段被点名，且出现在 ≥ 2 个章节；中 = 仅 1 处关键证据，或与其他文献并列引用；低 = 仅批量罗列，或仅出现在附录。 |
| R6 | **并列引用降档**：`"(A; B; C)"` 这类同括号并列，单个文献的把握程度降一档。 |
| R7 | **附录可见性**：默认管线在参考文献处停止扫描，只在附录详细对比的竞争者不可见；需要时开 `--appendix`。 |
| R8 | **不补位**：证据不足就交 1–2 篇并写明缺失信息，禁止为凑满 3 篇降低标准。 |
| R9 | **区分两类文献**：「本文要超越/对比的对象」（基线、SOTA、骨干）与「思想来源」（提供理论、方法、揭示空白）。只有后者进结果。 |
| R10 | **章节权重可信性**：章节识别一旦失效，权重会反转（方法章可能压过引言），此时排序整体不可信，一律以 S7 人工证据为准。 |
| R11 | **中文稿件**：线索词未在中文语料上验证，必须逐条人工复核，不得直接采信自动功能分类。 |
| R12 | **数据/工具/代码类引用**：直接判为次要，不进候选（属「使用」非「启发」）。 |
| R13 | **隐性启发是本质盲区**：全文从未点名的文献，本流程无能为力，需要外部共引数据才能覆盖。 |

## 八、异常处理速查

| 现象 | 定位步骤 | 首选动作 |
|---|---|---|
| 上下文数 = 0 | 查 `meta.json` 的 `style` 是否与正文一致 | `--style <STYLE>` 显式指定 |
| 参考文献数 = 0 | 查参考区是否被定位；书目是否无编号 | `--refs <REFS>` |
| 参考文献数异常（过多/过少） | 打印参考区首尾单元确认边界 | `--refs <REFS>` |
| 上下文集中单一章节 | 打印章节分布；检查标题行样式 | 不改脚本，S7 按 `page` 人工回查 |
| 题名 = 整条书目原文 | 查 `refs_nodes.json` 的 `title` 字段 | `--refs <REFS>`；或人工抄 `raw` |
| 年份缺失 | 统计 `year` 空值比例 | `--metadata` 联网补全 |
| 关键证据句被截断 | 用 `contexts.json` 的 `page` 定位 | 人工读取原页完整段落补录 |
| Top1/第4名 < 2.0 | S6 自动判定 | 排序仅作候选，走 S7 |
| LLM 输出无原文锚点 | 检查是否输出了 `insufficient` | 判定不可采信，回到 S7 |

## 九、成本参考（token 预算）

按环节拆分。**成本的大头是 Agent 的编排轮次，不是论文内容本身。**

| 环节 | Token 量 | 说明 |
|---|---|---|
| S0–S6、S9（脚本） | **0** | 纯本地 Python，不调用任何模型 |
| S8 LLM 裁决 | **8k–11k / 篇** | 实测提示词 24.5k–31.0k 字符（英文约 4 字符/token）+ 输出 1.5k–3k |
| S7 Agent 人工裁决 | **30k–80k / 篇** | 15–20 轮调用，论文内容仅占 10–15k，其余为系统提示与累积历史的重发 |
| 调试轮次（修抽取、重跑） | 每次重跑 +5k–15k | 不可预测，是超预算的主因 |

**体积实测（决定是否值得读进上下文）**

| 文件 | 字符数 | 折算 token | 建议 |
|---|---|---|---|
| `sentences.json` | ~157k | ~39k | **禁止整读**，仅脚本内部使用 |
| `seeds_ranked.csv` | ~33k | ~8k | 只读前 12 行 |
| PDF 全文（20 页） | ~75k | ~19k | 不整读，按关键词定向检索 |
| `seeds_evidence_pack.md` | 23k–30k | 6k–8k | 可读，但只取前 8 名 |
| `contexts.json` | ~43k | ~11k | 按需按 `ref_id` 过滤后读 |

**四条压缩成本的操作**

1. S3–S6 合并为一条 shell 调用（抽取 → 排序 → 打印校验指标一气呵成），省 4 轮。
2. S7 只读证据包前 8 名 + 定向检索原文，不读全表、不读 `sentences.json`。
3. 若可接受略低的可审计性，用 **S8 替代 S7**：把 15–20 轮压成 1 次 8–11k 的调用，成本降一个数量级（提示词已强制要求逐字原文 + 章节页码）。
4. 一篇论文一个会话；完成后开新会话，避免历史累积抬高每轮重发成本。

- [ ] 若 Top1/第4名 < 2.0，已在交付文档中注明排序未用于定序
