# 复用指南：三个入口怎么选、怎么跑、怎么维护

> 一句话：**日常单篇走 v2，批量圈候选走 batchrun，改完脚本跑冒烟测试，只有排障才回退 v1。**

## 〇、完整示例（端到端，照着跑一遍就会）

用一篇**没跑过的新论文**演示全程。样本：arXiv 2605.06467
《No Triangulation Without Representation: Generalization in Topological Deep Learning》（21 页）。

### 第 0 步：目测参考文献条数（唯一不能自动化的一步）

翻到文末看最后一条编号。这篇书目在第 9–12 页，末条是 `[42]`。

```bash
<PY> -c "
import pymupdf
d=pymupdf.open(r'<PDF_DIR>/2605.06467.pdf')
print(d[len(d)-1].get_text()[:600])   # 末页若是附录，往前翻一页
"
```

### 第 1 步：一键跑（唯一必需的命令）

```bash
cd <SKILL_DIR>/scripts
<PY> autorun.py "<PDF_DIR>/2605.06467.pdf" --out demo_notri --expect 42
```

实际输出：

```
[S1] pages=21 首页字符=2432 文本层=OK
[S2] numeric=74 authoryear=1 → 推测制式=numeric
[S3] refs=42 ctx=52 被引=37
[S4] C1=OK | C2=OK | C3=OK

     C5=OK | C6=OK
[!!] 未通过 C4 → 建议先按异常表处理
```

**怎么读**：C1/C2/C3 都 OK → 抽取质量没问题（42 条书目、52 条上下文、37 条被引，都对得上）。

<PY> autorun.py "<PDF_DIR>/2605.06467.pdf" --out demo_notri --expect 42 --force

### 第 2 步：人工裁决（A3）——比值 <2.0 时**必须**做

读 `<OUT>/seeds_evidence_pack.md` 里 Top3 的 ±2 句窗口，逐条回原文。
这一篇的裁决结果：

| 机器排名 | 编号 | 分数 | 裁决 | 理由 |
|---|---|---|---|---|
| 1 | [5] CW Networks | 13.44 | **降级** | 证据语境是"实现有缺陷、我们要修补它"→ 被对比的基线，非启发源 |
| 2 | [16] Topological blindspots | 12.46 | 保留第 2 席 | "complements the findings by [16]... whereas we demonstrate that they do not even learn the ones they are theoretically capable of learning" |
| 3 | [29] Pachner 1991 | 11.04 | 保留第 3 席 | 出现在贡献列表第 1 条："establishing Pachner moves [29]... as principled data augmentation and evaluation tools" |
| 4 | [2] MANTRA | 8.24 | **上调第 1 席** | "we extend MANTRA"——本文是它作者本人的延续工作，`RESOURCE` 线索给了 −4.18 误罚 |

**两个典型误判模式**（跟机器判据直接相关，值得记住）：
- **被批评得最多的那篇 ≠ 启发源**。`GAP` 线索不区分"缺陷属于谁"，被反复批评的基线反而分数最高。
- **数据集类文献被 `RESOURCE` 负分压下去**。当本文的立足点本身就是一个数据集/基准时，那篇就是核心启发（本篇的 [2] MANTRA 就是，且本文作者与前作作者重名）。

完整裁决与原文引句见 `demo_notri_核心启发文献.md`。

凑不满 3 篇就交 1–2 篇并写明缺什么，不要凑。

## 二、路径 A：单篇（日常，走 v2）

```bash
# A1 一键跑（唯一必需的一步）
<PY> autorun.py <PDF> --out <OUT> --expect <N>
```
`<N>` = 翻到文末目测的参考文献条数。**这是唯一不能自动化的一步**，别跳过。

看报告里的两行就够判断：
- `[S4]` 六条闸口判据 → 有 FAIL 就先按异常表处理（见 SOP v2 第三节）
- `[S6] Top1/第4名=X` → **X ≥ 2.0** 排序可定序；**X < 2.0** 排序只圈候选，必须人工读证据

需要深挖时（A3 定向裁决）：

```bash
<PY> -c "
import json,re,pymupdf
P = r'<PDF>'
ids = [<id1>,<id2>,<id3>]
n = {x['id']:x for x in json.load(open(r'<OUT>/refs_nodes.json',encoding='utf-8'))}
for i in ids: print(f'[{i}]', n[i]['raw'][:170])
d = pymupdf.open(P); t = ''.join(pg.get_text('text') for pg in d[:3])
for kw in ['inspir','motivat','however','to date','limitation','draw on','build on']:
    for m in list(re.finditer(kw,t,re.I))[:2]:
        s=max(0,m.start()-190); print('>',t[s:m.start()+170].replace(chr(10),' '))
"
```

完整 ±2 句证据窗口在 `<OUT>/seeds_evidence_pack.md`，按需读（**不要整读 `sentences.json`**）。

## 三、路径 B：批量圈候选（走 batchrun）

```bash
# 从 lit.db 按主题筛
<PY> batchrun.py --db <LITDB> \
    --where "q_tag='拓扑深度学习'" --out batch_topo --jobs 4

# 或从一个清单 / glob
<PY> batchrun.py --list pdfs.txt --out batch_x
<PY> batchrun.py --glob "<PDF_DIR>/*.pdf" --out batch_mag

# 小规模试水
<PY> batchrun.py --db <lit.db> --where "<SQL>" --out batch_x --limit 10
```

产出：
- `<OUT>/batch_summary.md` — 汇总表 + **需人工关注清单**（闸口失败或比值 <2.0 的）
- `<OUT>/batch_summary.csv` — 同内容的表格
- `<OUT>/<序号_文件名>/` — 每篇的完整产物，深挖时按路径 A 的 A3 读

**批量默认是 `--force`**（闸口失败也出候选），因为它定位是初筛：机器圈定 + 标记风险，人只看被标记的那几篇。
代价是把握度降一档，`把握` 列会写明。要严格走闸口就加 `--no-force`。

先 `--limit 10` 跑一批看看版式是否稳定，再放开全量。

## 四、路径 C：排障（回退 v1 分步）

触发条件：闸口连续失败 ≥2 次，或需要单独指定书目/制式/附录。

```bash
# S1 抽取（可单独调参，这是 v2 做不到的）
<PY> citeparse.py <PDF> --out <OUT> [--refs <BIB>] [--style numeric|paren|authoryear] [--appendix]

# S2 看抽取质量（v2 里这两步被折叠掉了）
cat <OUT>/meta.json                      # 条目数、上下文数、制式
#  章节分布：refs/ctx 是否集中在单一章节 → 章节识别失效

# S3 排序
<PY> seedfinder.py <OUT> --top 8 [--metadata]

# S4 读证据
cat <OUT>/seeds_ranked.csv
cat <OUT>/seeds_evidence_pack.md
```

常用调参：

| 症状 | 加什么 |
|---|---|
| 解析出的书目条数不对 | `--refs <BIB>`（.bib/.txt/.json） |
| 制式判错（`meta.json` 的 style 与目测不符） | `--style numeric` / `paren` / `authoryear` |
| 启发证据可能在附录的对比讨论里 | `--appendix` |

## 五、路径 D：改完脚本怎么确认没改坏

本便携版不含回归基线（原版 `regress.py` + `regress_baseline.json` 依赖本机 7 篇 PDF，无法随包分发）。
改用**冒烟测试**兜底：

```bash
cd <SKILL_DIR>/scripts
<PY> autorun.py "../smoke_assets/DiffLifting.pdf" --out smoke
```

判定：`refs=58 ctx=82 被引=45`、比值 `1.41`、`[report bytes = 2667]` 三项必须与改动前一致。
只要有一个数字变了，就说明抽取或打分被改坏了。

**想恢复完整回归**：把几篇覆盖不同版式的 PDF 放进 `smoke_assets/`，
自己维护一份期望值清单（书目数 / 上下文数 / 制式 / Top1 编号严格相等，分数与比值容忍 ±0.05），
改完脚本逐篇跑一遍比对即可。覆盖建议：数学稿 `[n]` 制、Science 裸数字制、
NeurIPS 双栏 LaTeX、IEEE、作者-年制、带公式编号的短文。

## 六、发现新版式怎么办（维护约定）

1. **先记缺陷号**（延续 D1–D9 编号），写清：症状、影响哪篇样本、修没修、为什么不修。
2. **先留样本**，再动代码——把这篇 PDF 存进 `smoke_assets/`，记下改动前的输出数字。
3. 改完跑第〇节的冒烟命令，确认原有数字没被带坏。
4. 若确认是有意改动 → 更新记录的期望值。
5. 同步更新 `SOP_核心启发文献识别_v2.md` 的异常表与规则表。

已知未修的：**D4** —— LaTeX 双栏/数学稿的章节编号与标题分行（`1⏎Introduction`）识别不到，
章节权重失效，由闸口 C4 报警兜底。修它需要按字号/bbox 做版面区分（图区的 `5⏎Loss`
这类坐标轴标签与真标题形状难分）——若动手修，须用多版式样本逐篇比对，别只看单篇。
