# 大批量实测：arxiv 混合目录 100 篇

> 目的：回答">40 篇要不要分小批处理"，并给出分批阈值的实测依据。
> 样本：`<PDF_DIR>`（894 篇混合版式，取前 100 篇）
> 环境：`--jobs 6`，WorkBuddy 受管 Python 3.13

## 一、结论先行

**跑（batchrun）不分批，裁决（review）才分批；推荐一批 10–15 篇，单次任务 ≤40 篇。**

- 分批的动机是**上下文**：解析是 IO+CPU 开销，几百篇几分钟；第 3 步读 digest
  才是内存杀手（约 500 字符/篇）。
- 但**批大小的动机是裁决质量，不是容量**：digest 装得下 50 篇，
  而 68% 的篇必须逐条读证据回原文核实，10 篇里有 7 篇要真花注意力。
  实测锚点 5 篇 ≈ 5k token（读 digest + 核实 + 写交付），即约 1k token/篇。
- **>60 篇不该用这个 skill**：用途已经变成"做领域综述"，改用 citegraph（共被引枢纽）
  或抽样 10–15 篇。详见 SKILL.md 第三节。

## 二、实测数据

| 篇数 | 耗时（增量） | digest 体积 |
|---|---|---|
| 12 | 7.1 s | 440 行 / 7k 字符 |
| 40 | 25 s（累计） | 1363 行 / 21k 字符 |
| 100 | 41.6 s（增量 60 篇） | 3307 行 / 52k 字符 |

外推：894 篇全量约 10 分钟。

### 100 篇的质量分布

| 项 | 数量 | 占比 |
|---|---|---|
| 闸口 OK | 44 | 44% |
| 闸口 FAIL | 41 | 41% |
| **FATAL（抽取失败）** | **15** | **15%** |
| 比值 ≥2.0（Top1 可直接采信） | 17 | 17% |

制式分布：numeric 60 / authoryear 30 / paren 10 —— 混合目录三种制式都有。

**两个必须写进交付说明的数字**：15% 抽取失败、83% 需要人工裁决（比值 <2.0）。
单一来源的目录（如 `PDFs/magnitude` 18 篇）失败率通常 <5%，混合目录才到 15%。

## 三、分批阈值怎么定的

- digest ≈ 500 字符/篇，约合 170 token/篇
- 50 篇 ≈ 26k 字符 ≈ 8k token —— 一次读完舒服
- 100 篇 ≈ 52k 字符 ≈ 17k token —— 能装，但会挤掉核实/写作的余量

所以定 **50 篇/批**。>150 篇时先按子目录或主题切成 ≤100 篇的组，
而不是硬跑全量（894 篇要 18 批，且失败清单本身就很长）。

## 四、本轮为此补的两个能力

| 能力 | 命令 | 用途 |
|---|---|---|
| `--skip-done` | `batchrun.py ... --limit N --skip-done` | 同一 `--out` 续跑，跳过已完成，汇总表仍含它们。分批只需不断加大 `--limit` |
| `--range a-b` | `review.py <OUT> --range 1-50` | 按序号分批生成 digest |

## 五、本轮修掉的 bug（都是大批量才暴露的）

### B1 单篇崩溃 → 整份报告丢失，闸口误判 OK

`autorun.py` 的输出函数 `P()` 只把行累积进列表、末尾统一 `print`。
一旦中途崩溃（实测 `seeds_ranked.csv` 为空时 `rows[0]` IndexError），
**stdout 全空**，而 `batchrun.parse()` 的 `gate` 默认值是 `"OK"` ——
失败篇就这么混进了"闸口 OK"里。

修法三处：
1. `P()` 改为实时打印（崩溃时已完成的步骤仍留在 stdout）
2. `rows` 为空时不崩，明确输出 `[FATAL] 无候选（refs=… ctx=…）`
3. `batchrun.parse()`：报告为空 / 含 FATAL / 含 Traceback / 超时 → `gate = "FATAL"`

### B2 `--skip-done` 会把崩溃篇永久跳过

判据原本是"报告文件存在"，而崩溃篇的报告文件存在但为空 → 永远不再重跑。
改为**存在且非空**。

### 效果

修复前 40 篇：闸口 FAIL 21 / OK 19，其中 4 篇实际是崩溃（被误报 OK）。
修复后 40 篇：FAIL 21 / OK 15 / **FATAL 4** —— 失败被正确暴露。

## 六、实操命令

```bash
PY="<PY>"
cd <SKILL_DIR>/scripts

# 1) 试水（任何规模都先做，看版式与 FATAL 率）
$PY batchrun.py --dir "<文件夹>" --recursive --out <OUT> --limit 12 --jobs 6

# 2) 一次跑完（不必分批；重复调用只会补跑）
$PY batchrun.py --dir "<文件夹>" --recursive --out <OUT> --jobs 6 --skip-done

# 3) 分批裁决
$PY review.py <OUT> --top 3 --range 1-50
$PY review.py <OUT> --top 3 --range 51-100
```

> ⚠️ 批量模式无 `--expect`，C1（书目条数校验）缺席，交付时要说明。
