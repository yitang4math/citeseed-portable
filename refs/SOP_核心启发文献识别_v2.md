# 标准工作流 v2（精简降本版）：单篇论文「核心启发文献」识别

> v2 = v1 的**批处理化**版本：把 v1 的 S1–S6 六个独立步骤折叠为**一次调用**，
> 中间产物全部落盘不进上下文，只输出一份精简报告。
> **两者用的是同一套脚本与同一套判据，结果完全一致**（已在两篇新样本上验证，见对比报告）。

## 与 v1 的关系

| | v1（全审计版） | v2（精简版） |
|---|---|---|
| 步骤数 | S0–S10 | A1–A4 |
| 脚本调用轮次 | 6 轮/篇 | **1 轮/篇** |
| 产物 | 全部落盘，逐项人工查看 | 全部落盘，只看精简报告 |
| 适用 | 首次接触新出版样式、需要排查抽取质量、需要全量审计 | **日常批量处理**（版式已知、抽取稳定） |
| 回退条件 | — | 闸口连续失败 ≥2 次 → 回退 v1 逐项排查 |

## 一、输入说明

| 输入项 | 必需性 | 要求 |
|---|---|---|
| 论文 PDF | **必需** | 文本型（可复制文字）；扫描件先 OCR |
| 参考文献总条数 `<N_expected>` | **必需**（对应 v1 的 P5） | 人工翻到文末目测，作为 C1 判据的分母。**这是唯一不能自动化的一步** |
| 参考文献文件 | 可选 | 仅当自动解析失败时提供（`.bib`/`.txt`/`.json`） |
| LLM API Key | 可选 | 配置后可进一步把 A3 压成 1 次调用（见第五节） |

## 三、流程

### A1 一键运行（覆盖 v1 的 S1–S6）

- **前置条件**：P1–P5 完成。
- **输入**：`<PDF>`、`<OUT>`、`<N_expected>`。
- **动作**：

```bash
<PY> autorun.py <PDF> --out <OUT> --expect <N_expected>
```

常用变体：

| 场景 | 追加参数 |
|---|---|
| 自动解析的参考文献数不对 | `--refs <REFS>` |
| 引用制式判定错误 | `--style numeric` / `--style paren` / `--style authoryear`（`paren` = Science/Nature/Cell 的上标括号数字 `(31)`） |
| 需要覆盖附录中的对比 | `--appendix` |
| 闸口未通过但已评估风险、仍要继续 | `--force`（报告会提示「把握程度整体下调一档」） |
| 想看更多候选 | `--top 12` |

- **预期输出**（单份报告，实测 2.5–2.8 KB）：

```
[S1] pages=20 首页字符=3043 文本层=OK
[S2] numeric=0 authoryear=18 → 推测制式=authoryear
[S3] refs=18 ctx=21 被引=16
[S4] C1=OK | C2=OK | C3=FAIL(ctx=21<1.2×18)
     C4=OK
     C5=OK | C6=OK
[S6] Top1/第4名=2.11 → 排序可用于定序
[TOP16]
  1.[ 5]   5.49 中  数据与资源              次 2 Matrix Computations
  ...
[EV ] 最强证据（逐字，供人工回查）
  1.[ 5] §RELATED WORK p.3 :: Procrustes analysis is the canonical example, ...
[NEXT] 下一步：对 Top3 逐条回 PDF 原文核实；凑不满 3 篇就交 1-2 篇并写明缺失信息。
```

- **校验点**：`[S1] 文本层=OK`；`[S4]` 六条判据无 FAIL；`[EV ]` 的证据句与 `[TOP]` 的 ref_id 对得上。
- **异常处理**：
  - `文本层=FAIL` → 扫描件，先 OCR 再重跑。
  - `C1 FAIL` → 解析数与目测数不符 → 加 `--refs`。
  - `C3 FAIL`（上下文偏少）→ 多为引用匹配失败 → 加 `--refs` 或 `--style`。
  - `C4 FAIL` → 章节识别失效（**已知 D4**：LaTeX 双栏/数学稿的章节编号与标题分居两行时识别不到，
    表现为"最大占比 = 全部上下文"）→ 章节权重失效，以 A3 人工证据为准；实测线索词 + 出现次数仍能
    把正确文献排到 Top1，可用 `--force` 带缺陷继续。
  - `C5 WARN` → 加 `--style` 显式指定。
  - **连续两次仍失败 → 停止，回退 v1 逐项排查。**

---

### A2 闸口判定

- **前置条件**：A1 输出已读。
- **输入**：报告中的 `[S4]` 与 `[S6]` 两行。
- **动作**：按下列规则判定，无需额外调用。
  1. `[S4]` 有 FAIL → 按 A1 异常表处理，不进入 A3。
  2. `[S6] Top1/第4名 ≥ 2.00` → 排序可用于定序；`< 2.00` → **排序只用于圈定候选**，A3 必须逐条看证据。
  3. 行尾标「次要」的不进前 3 名。
- **预期输出**：一个明确的候选清单（通常 3–8 篇）。
- **校验点**：候选数 ≥ 1；若 `--force` 生效，把候选的把握程度整体下调一档。

---

### A3 定向裁决

- **前置条件**：A2 完成。
- **输入**：候选 ref_id 列表 + PDF 原文。
- **动作**：**一次调用**完成三件事——补题录、取动机句、取候选全部上下文：

```bash
<PY> -c "
import json,re,pymupdf
P = r'<PDF>'
ids = [<id1>,<id2>,<id3>]
n = {x['id']:x for x in json.load(open(r'<OUT>/refs_nodes.json',encoding='utf-8'))}
for i in ids: print(f'[{i}]', n[i]['raw'][:170])
d = pymupdf.open(P); t = ''.join(pg.get_text('text') for pg in d[:3])
for kw in ['inspir','motivat','however','to date','limitation','draw on','build on']:
    for m in list(re.finditer(kw,t,re.I))[:2]:
        s=max(0,m.start()-190); print('>',t[s:m.start()+170].replace(chr(10),' '))
"
```

> **题录取自 `raw` 字段**：`seeds_ranked.csv` 的「题名」列在部分版式（IEEE 数字制）下会退化成刊物名片段，
> 不要直接引用该列，一律回 `refs_nodes.json` 的 `raw`。

- **预期输出**：候选题录 + 含 `inspired / motivated / however / limitation` 的原文片段。
- **校验点**：至少 1 条片段能直接支撑某候选的「启发」判定；否则该候选把握降为「低」。
- **异常处理**：证据仍不足 → 不补位，按 R8 写明缺失信息。

---

### A4 交付

- **前置条件**：A3 完成。
- **动作**：按 v1 第六节的交付文档模板填写；产物目录结构与 v1 的 S10 相同。
- **校验点**：每篇核心文献 ≥ 1 条逐字原文 + 章节 + 页码；不满 3 篇时写明缺失信息。

---

## 四、降本操作清单（v2 相对 v1 的四处改动）

1. **S1–S6 折叠为一次 `autorun.py` 调用**：轮次 6 → 1。
2. **中间产物只落盘不展示**：`contexts.json`（~43 KB）、`sentences.json`（~157 KB）、
   `seeds_ranked.csv`（~33 KB）**禁止整读**，只在脚本内部使用。
3. **报告内置截断**：题名截 42 字符、证据句截 150 字符，单份报告控制在 ~2.8 KB。
4. **A3 一次调用合并三件事**（题录 + 动机句 + 候选上下文），不分开查。

---

## 五、进一步降本（需 LLM_API_KEY）

配置 `LLM_API_KEY` 后，可把 A3 也替换为一次调用：

```bash
<PY> seedfinder.py <OUT> --llm
```

成本约 **8–11k tokens/篇**，替代 A3 的 15–20 轮人工核查。
提示词已强制要求逐字原文 + 章节 + 页码，证据不足输出 `insufficient`；
**仅在对可审计性要求不高时使用**，正式结论仍建议走 A3。

## 六、成本实测（五篇样本：两篇旧 + 三篇新，见两份对比报告）

| 指标 | v1 | v2 | 变化 |
|---|---|---|---|
| 脚本调用轮次 | 6 | **1** | −83% |
| 脚本产出字节 | 2,524–3,041 | 2,503–2,801 | −8% |
| 含裁决总轮次（三篇新样本稳态合计 15 → 5） | 15 | **5** | −67% |
| agent 读入字节（三篇新样本 ≈22 KB → 7.9 KB） | 22 KB | **7.9 KB** | −64% |
| 折算 token（按每轮 ~3.5k 固定开销估） | ~25–35k | **~8–12k** | **−65%** |

**关键结论**：v2 省的是**轮次带来的固定重发开销**，不是内容——两版读到的内容量几乎相同
（甚至 v2 更多，因为它顺带给出了逐字证据句）。

**五篇样本的结论一致性**：参考文献数、上下文数、被引覆盖、Top1、Top1/第4名比值、候选清单——
逐项相同，两流程用的是同一套判据。

## 七、通用规则

沿用 v1 第七节的 R1–R13，此处不重复。v2 新增八条：

| # | 规则 |
|---|---|
| R14 | **`--force` 是降级开关**：一旦使用，候选把握程度整体下调一档，并在交付文档中注明带缺陷继续。 |
| R15 | **题录以 `raw` 为准**：排序表的「题名」列可能退化，禁止直接抄进交付文档。已实测到的退化版式：IEEE 数字制（题名→刊物名片段）、Science 制（题名→`Sci. Adv` / `Nature 595, 80–84`）、博客评论类条目（两条不同文献同名）。 |
| R16 | **启发强度与文献的正式程度无关**：纯数学稿的启发来源可能是博客评论或未发表手稿（实测 P1 的 Top1 是 n-Category Café 的评论）。不要因为题录"不像论文"就把候选剔除。 |
| R17 | **`RESOURCE` 负分会把"本文立足的数据集"误杀**：当一篇论文的贡献就是扩展/重做某个数据集或基准时，那篇数据集论文就是核心启发，但 `RESOURCE` 会重罚它。实测 NoTri（arXiv 2605.06467）：[2] MANTRA 出现 4 次、`RESOURCE −4.18`，被压到第 4，而人工裁决它是第 1 席（本文作者与前作作者重名）。**A3 时对所有"数据集/基准"类候选单独复查一次**，看它是否出现在贡献列表里。 |
| R18 | **`GAP` 线索不区分"缺陷属于谁"**：被反复批评的那篇往往是**被修补的基线**，不是启发源，却因为 GAP 命中次数最多而排到机器第一（实测 NoTri 的 [5] CW Networks，13.44 分排第 1，实为基线）。**A3 时对每个机器 Top1 都问一句：这些缺陷是本文要解决的，还是本文从它那里继承的动机？** |
| R19 | **`INSPIRE` 线索不判方向**。"Motivated by our work, X proved…" / "Following our paper, X…" 指的是**本文的下游**被引，不是启发源。实测 magnitude 专题 001 篇：Meckes [15] 因此被误排机器第一（17.39），实为本文启发了他。**对每个 `INSPIRE` 命中都要确认主语：是"本文启发了谁"还是"谁启发了本文"。** |
| R20 | **区分"方法的来源"与"方法的外延"**。同作者前作常出现在"本文方法可推广到 X"的语境里（002 篇的 [14] Spread、004 篇的 [28] 部分），那是本文的**贡献外延**，不是启发源。 |
| R21 | **"领域起源引用"不一定是本文的启发源**。若本文只是顺带提到某概念的首创者（如 005 篇的 [10] Leinster，magnitude 概念首创），那是常识性引用，应剔除。**例外**：当本文的立意正是把某领域的概念移植过来时，那篇起源文献**就是**核心启发（001 篇的 [17] Solow & Polasky 1994——magnitude 在生态学以"effective number of species"首次出现）。判据：本文是否明确说"这个概念来自 X 领域"。 |
